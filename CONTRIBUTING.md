# Contributing Guidelines

Thank you for helping keep this DSA learning workspace consistent and easy to review. Follow the standards below when adding or updating notes.

---

## Scope

- One topic per markdown file.
- Use clear, beginner-friendly explanations.
- Focus on correctness, clarity, and revisability.

---

## Folder Structure

When adding or updating content, please adhere to the following structure:

- `notes/`: Comprehensive topic files following the full Note Structure below.
- `short-notes/`: Brief, focused explanations for specific concepts.

---

## File Naming

- Use concise, title-case filenames without spaces when possible.
- Examples: `Arrays.md`, `BinarySearchTrees.md`, `DynamicProgramming.md`.

---

## Note Structure

Use the same section order for every topic file.

```markdown
# Topic Name

## Definition

## Intuition

## Why It Matters

## Example

## Approach

## Code Example

## Time Complexity

## Space Complexity

## Common Mistakes

## Important Questions

## Revision Notes
```

---

## Content Standards

- **Definition**: 2-4 lines, plain language.
- **Intuition**: include a mental model or visualization.
- **Example**: add a small input and a step-by-step walkthrough.
- **Approach**: outline steps before code.
- **Complexity**: use Big-O; justify when not obvious.
- **Common Mistakes**: list 2-4 pitfalls.
- **Important Questions**: include 3-6 practice prompts.
- **Revision Notes**: keep short bullet updates with dates if helpful.

---

## Code Standards

- Prefer C++ for code examples unless the topic requires another language.
- Keep code minimal and focused on the core idea.
- Add brief comments only where a tricky step is easy to misread.
- Use consistent input/output assumptions and, when possible, match the workspace `input.txt` and `output.txt` flow.

---

## Formatting Standards

- Use `#` for the topic title and `##` for sections.
- Keep line length reasonable for reading in VS Code.
- Avoid unnecessary emojis or casual tone.
- Keep examples small enough to compute by hand.
